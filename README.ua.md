# Оцінка безпеки платформи AI-агентів (Agent Platform Security Assessment)

Оцінка безпеки платформ штучного інтелекту на GCP, що складається з сімнадцяти перевірок та рівнів доказів.
Доповнення до статті ["Безпека як код: Оцінка безпеки платформи AI-агентів"](https://d3ep0ps.com) та
серії *Безпека як код: Безпека AI-агентів* на [d3ep0ps.com](https://d3ep0ps.com).

## Метод

Три межі, що оцінюються за трьома рівнями доказів:

| Рівень | Значення |
|---|---|
| **Документовано** | Контроль існує в політиці чи вікі |
| **Налаштовано** | Контроль існує в живій конфігурації — ви можете надати вивід команди для нього вже сьогодні |
| **Примусово** | Обхід контролю вимагає зміни коду або призводить до збою розгортання |

**Правило:** відповідь зараховується лише на тому рівні, для якого ви можете надати докази за запитом.
Відповідайте на кожну перевірку посиланням на код або виводом команди — ніколи не обмежуйтеся зустріччю.

## Три межі

| Межа | Запитання | Ризики OWASP ASI |
|---|---|---|
| **Досяжність (Reach)** | До чого може дотягнутися агент, якщо його обдурять, і чи дотримується він лімітів ресурсів? | ASI01, ASI02, ASI05, ASI08 |
| **Ідентичність (Identity)** | Хто може говорити з агентом, від чийого імені він діє та чи захищені логи від видалення? | ASI03, ASI07, ASI10 |
| **Походження (Provenance)** | Звідки взялася модель — чи помітите ви заміну? | ASI04, ASI06 |

## Як запустити оцінку

1. Відкрийте [`assessment.ua.md`](assessment.ua.md) — кожна перевірка містить *що запитати*, *як виглядає добрий стан* та команду *верифікації*.
2. Записуйте результати в [`scoring-sheet.ua.csv`](scoring-sheet.ua.csv) — один рядок на кожну перевірку: досягнутий рівень + посилання на докази.
3. Оцініть кожну межу від 0 до 3 (див. нижче). Запишіть результат як три цифри: **Досяжність / Ідентичність / Походження**.
4. Збережіть заповнену таблицю у репозиторії вашої платформи. Повторюйте оцінку щоквартально; diff (різниця) буде вашим звітом про відхилення (drift report).

## Оцінювання

| Бали | Значення |
|---|---|
| 0 | Одна або кілька перевірок повністю провалені (дефолтний SA, експортований ключ, відсутність пісочниці) |
| 1 | Перевірки пройдено лише на рівні Документовано |
| 2 | Більшість перевірок Налаштовано — сьогодні надано вивід команд |
| 3 | Елементи контролю Примусово — обхід вимагає зміни коду або збою розгортання |

Ідеальний результат 3/3/3 підтверджує факти про артефакти, ідентичності та конфігурацію.
Атаки живуть у поведінці — дивіться прикінцевий розділ статті, щоб дізнатися, що ця оцінка свідомо не покриває.
